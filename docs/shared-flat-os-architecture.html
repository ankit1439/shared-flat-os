A. Product architecture

One flat. Four people who already trust each other. One website they can install as a PWA. It should answer everyday questions without WhatsApp maths:

  • Who is at the flat?
  • Who paid for milk / sabzi / bill?
  • What was added, when, by whom, at what price?
  • Who owes whom — and has the other person confirmed the cash/UPI?
  • What did we spend this month?
  • Whose chore / who has the key / what is broken?

System shape

Four phones (browser or installed PWA)

D. Presence — can home Wi-Fi mean someone is home?

Yes — that is the right idea for this flat. GPS is the wrong idea. If a roommate’s phone is connected to the flat Wi-Fi, they are almost certainly at home. We should use that. We should not build background GPS tracking.

Honest limit (do not skip this)

The website running on the phone cannot read the Wi-Fi name (“JioFiber-5G” vs college Wi-Fi). iOS Safari, iOS PWA, Android Chrome, Android PWA — all block SSID / BSSID for privacy. So this will not work:

// this is impossible in a browser
if (wifiName === "Flat-WiFi") markAtHome();

Detection has to happen from inside the home network: “which known phones are currently connected to our router?”

How we will do it (simple, for four people)

MethodHowAutomatic?
Home beacon (best) A tiny always-on thing on flat Wi-Fi — old phone left charging, laptop, Raspberry Pi, or a script on the router if it allows. Every few minutes it looks at connected devices and tells the app: Ankit’s phone is here, Rahul’s is not. Yes — nobody opens the app
Open-app ping When someone opens the PWA, the site tries a local URL that only exists on home Wi-Fi (e.g. http://192.168.0.50:8787/here). If it succeeds, that person is At Flat. Only when the app is opened
Planned away “Rahul home 20 Aug–10 Sep” still shows away even if the phone is off. Manual calendar
Fallback tap Small “I’m home / I’m out” only if beacon is down. Not the daily ritual. Manual

One-time phone setup (needed so Ankit ≠ “some iPhone”)

Modern phones hide their real identity on Wi-Fi (Private Wi-Fi Address / randomized MAC). For this home network only, each roommate should:

  • iPhone: Settings → Wi-Fi → (i) next to flat Wi-Fi → Private Wi-Fi Address → Off (or Fixed, then we save that MAC once).
  • Android: Wi-Fi → flat network → Privacy → Use device MAC.
  • Then in People → My devices → “This is Ankit’s phone” (beacon records the MAC / name once).

After that the beacon can tell Ankit vs Rahul. Turning this off only for home Wi-Fi is normal and safe inside your own flat.

What can go wrong (we show UNKNOWN, we do not guess)

SituationApp shows
Phone on flat Wi-FiAt Flat
Phone on mobile data / college Wi-FiAway (or Unknown if we never saw them leave)
Wi-Fi off / battery saver killed Wi-Fi / phone deadUnknown — “signal unavailable”, not fake Away
Phone left at flat, person went to collegeAt Flat (same lie GPS would tell). Accept it, or they tap I’m out.
Guest uses Wi-FiNot a roommate unless we map that device
Wi-Fi reaches the building gateMay show At Flat while just outside — good enough for a flat
Beacon unpluggedUnknown for everyone until it is back; open-app ping still works
We will not do Background GPS, geofences in the PWA, storing location trails, or claiming the browser can see your SSID. Wi-Fi-from-the-router is the honest automatic path for four people in one home.

Type chips: milk | vegetables | groceries | food | household | rent | electricity | wifi | other. Monthly report groups by these. Bills on the home UI can roll rent + electricity + wifi together.

Balance: paid − share + approved settlements received − approved settlements sent. Claimed-but-not-approved does not change the balance.

I. Simple rules — not a bank

Only these four people will use it. We will not build OAuth, App Review, rate-limit dashboards, or invite RBAC. We still keep money honest.
